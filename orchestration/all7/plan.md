## Architecture Decision

- **Stack:** unchanged from the repo — Python 3.12, `agentorch` on `PYTHONPATH`,
  boto3, `bedrock-agentcore` runtime SDK, Docker buildx (linux/arm64), pytest.
  No new stack is justified: the whole point is that the *released* modules run
  unmodified, so introducing anything new would undermine the claim being made.

- **Diagram:**

```
  harness (local)                 AgentCore Runtime (us-east-1)
  ┌──────────────┐   Invoke      ┌──────────────────────────────┐
  │ run_all7.py  │ ────────────▶ │ agent_app.py                 │
  │ records .jsonl│               │  ├─ imports agentorch.*      │
  └──────────────┘               │  ├─ pattern = P<N>(...)      │
                                 │  └─ SEAM SWAP:               │
                                 │      pattern.bedrock    = ●  │
                                 │      pattern.agentcore  = ●  │
                                 │      pattern.guardrails = ●  │
                                 └───────────┬──────────────────┘
                                             │ live calls
              ┌──────────────┬───────────────┼──────────────┬─────────────┐
              ▼              ▼               ▼              ▼             ▼
        Converse API   AgentCore Memory  AgentCore GW   ApplyGuardrail  CloudWatch
        (P1..P7)        (P4, P6)          (P5)           (P6)           (P3)
```

- **Data model:** unchanged. `WorkItem` / `WorkResult` / `CallContext` are the
  repo's own. No task may alter them.

- **Verification strategy:**
  1. *Contract tests* (offline) assert each live client exposes a
     signature-compatible method for every mock method the patterns call. This is
     what keeps the "single seam" claim true as either side changes.
  2. *Stub tests* (offline) run all seven released patterns through stub live
     clients and assert each pattern's structural signature — invocation and
     service-call counts — so a regression is caught before any spend.
  3. *Standalone smoke* per live method against the real service, before it is
     wired into a pattern. The C3/C4 counter bug was caught exactly this way.
  4. *Live runs* with structural assertions, not just success counts.
  5. The existing 242-test suite must never regress.

- **Verify command:** `python -m pytest -q`

- **External boundaries never crossed autonomously:** creating or deleting AWS
  resources, changing IAM, spending on live model calls, deleting or overwriting
  any committed result under `anchor/results/` or `anchor/p7/results/`, editing
  the manuscript, publishing a release or DOI.
